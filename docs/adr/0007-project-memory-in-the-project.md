# 0007 · Project memory lives in the project

**Status:** accepted (2026-10-03, Waymark 2.0.0-dev). Moves the project memory and the provenance log of 0001–0006 into the project; the chain format does not change.

## Context
Each project's memory (`~/.waymark/projects/<slug>.md`) and its provenance log (`~/.waymark/provenance/<slug>.jsonl`) lived in the user's home folder, and a project was found by the `Path:` line of its memory file. That lookup was written twice (`provenance.mjs`, `session-hook.mjs`). Another agent (Codex, Cursor) or a new session opened in the project could not tell where the work stood without knowing Waymark's home layout. Step 2 of Waymark 2.0 asks for the opposite: from the project folder alone, any agent should answer "which task am I on, what is missing, what was completed".

## Decision
Each project keeps its Waymark state in `<project>/.waymark/`, local and never committed: `.waymark/` is added to `.git/info/exclude`, which is untracked, so no tracked file changes. The folder holds plain files any agent can read:
- `memory.md`: the project memory, unchanged in format. The agent writes its task's *Work in progress* line here.
- `tasks.md`: generated by the end-of-turn hook from `memory.md` (*Work in progress*: in progress, pending, next step) and `provenance.jsonl` (done tasks with result and routine score). The agent never edits it, so it cannot contradict the record.
- `provenance.jsonl`: the hash-chained log, moved byte for byte so the chain still verifies.
- `README.md`: what each file is, for an agent that has never seen Waymark.

**One resolver** (`projectHome(cwd)` in `provenance.mjs`) is used by every hook. It walks up from the working folder to the nearest `.waymark/memory.md`, the same way git finds `.git`; the home folder itself is skipped. If none is found and an old `~/.waymark/projects/<slug>.md` matches, that is a **bridge**: the hooks read and write the old files, and the session hook offers the migration once, through the choice window (`migrate-memory.mjs`, a dry run by default, `--apply` after the user's yes; it backs up first, verifies the chain, writes the exclude line and leaves a `Moved:` stub in the old file). The bridge is removed in 2.1.0. With no memory at all, a git repository gets `<root>/.waymark/` and a folder outside git keeps the home layout.

**Other agents find the folder** through the Waymark block in each agent's user-level instructions file ("a `.waymark/` folder in the project → read `tasks.md`, then `memory.md`"), not through a tracked `AGENTS.md`. engram keeps cross-project lessons plus a task index: at each close the agent saves it with `mem_save` (`topic_key waymark/tasks/<slug>`), which is recorded and not blocked.

## Alternatives considered
- **Permanent fallback (strangler without an end date):** rejected. Two layouts would live side by side for good, and each hook would keep its own lookup.
- **Cut over in the install update (migrate every project listed in `projects.md`, no fallback):** rejected. A project missing from the index would silently lose its memory.
- **Migrate automatically at session start:** rejected. A hook would write project files without asking the user.
- **Pointer line in the project's `AGENTS.md`:** rejected for now. It is a tracked file shared with the team.
- **The agent writes `tasks.md`:** rejected. A hand-written list drifts from the record, the same failure as the three drifting sources of 0006.

## Consequences
- Positive: an agent that does not know Waymark can resume from the project folder alone. The memory travels with the project folder (a copy, a second machine with the same checkout). There is one place that resolves the project, and `tasks.md` cannot drift.
- Negative: memory is now per checkout, so a second clone starts without it. The block grows by one line until step 3 trims it. The bridge code stays until 2.1.0.
- Follow-up: step 2 (b) contract refinements and (c) quota calibration; remove the bridge in 2.1.0.
