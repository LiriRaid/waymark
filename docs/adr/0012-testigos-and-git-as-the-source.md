# 0012 · Testigos, one decision, git as the source of truth, and a fixed context card (step 3e)

**Status:** proposed (2026-10-04, Waymark 2.0.0-dev, step 3e). Every pick below is the user's (2026-10-03 · T2p). It will supersede parts of 0005, 0006, 0007 and 0010 as each sub-step lands. 3e-1 landed (2026-10-04 · T2q, below).

## Context
The 3c tests (Claude with Opus and Sonnet, Codex rollouts) kept producing false ✘. Almost all of them came from the hook reading prose the agent writes:
- Cierre fields spread over several lines;
- " · " used as a separator;
- quotes with "…";
- "Docker" read as "docs";
- a mention of `## Cierre` inside a sentence.

Each task is also written up to six times:
- `provenance.jsonl`;
- the *Work in progress* line of `memory.md`, which grows without limit (Waymark's T2 line is thousands of characters);
- `tasks.md`;
- the engram index;
- the commit;
- CHANGELOG and ADR.

The cost that matters is context re-read in every response: about 145k tokens × 103 responses in one task. Memory between sessions costs little next to that. The session-start digest (~2.7k characters) and the instructions block (~9.8k characters) are loaded every session.

## Decision
A **testigo** answers "is it true that…?" by **executing**, never by reading prose or giving an opinion. Each testigo:
- has an ID and lives in one catalog;
- states the claim it checks;
- runs a command;
- returns a deterministic verdict (✔ / ✘ / not applicable) with its evidence;
- can always be run again, by the hook or by hand.

The routine contract becomes the list of testigos that apply at each level. Step 3e lands in four parts. Each part is installed and tested by the user with Claude only before the next one starts:
1. **3e-1: testigos, one decision, secrets.**
   - The catalog, starting with: commit + trailer, final gate, decision, memory holds the task, review at L2+, chain intact, no secrets.
   - The decision is the user's answer in the choice window, recorded as is. The agent no longer restates it.
   - The Cierre shrinks to what no testigo can know.
   - **Gate testigo:** the exit code of the gate the agent ran after the last change counts. With none, the testigo runs the repo's typecheck; the hook never runs the full build.
2. **3e-2: git as the source of truth.**
   - The commit says what was done.
   - The task's record (decisions, verdicts, tokens, time) is attached as a git note (`refs/notes/waymark`). `provenance.jsonl` keeps only what has no commit.
   - `tasks.md` is generated from git and the live task.
   - `memory.md` holds the live state (≤200 characters per task) and stable facts, written by the hook.
   - One index.
   - Code comments say how the code works and what it is for, never task history.
3. **3e-3: context and adaptation.**
   - A fixed context card at session start (~300–500 tokens) generated by the hook. Everything else is pulled on demand with short queries.
   - A per-task pack keyed by the files the task touches.
   - A "next task in a new session" notice when the context is large.
   - The stack is read from the repo on every task.
   - **Incidents:** incident → cause → what it taught → result. An incident closes only when its testigo passes on a later task; repeated ones become department or stack rules.
4. **3e-4: shorter, specific rules, measured.**
   - The reminder, the instructions block, the departments and the skills keep only what testigos do not check.
   - Every "MUST" becomes a testigo or is removed.
   - Tokens are measured before and after: session start, resume, per task (including subagents), card and reminder size.

### 3e-1 as built (2026-10-04 · T2q, the user's picks)
- **Catalog:** `routine.json` itself (`testigos`: id, label, levels, when, enforce, claim). The checks that need a process or git live in `scripts/testigos.mjs`, which also re-runs them by hand. The other steps (procedure, mem_search, index, build, spec, red, pre-existing, docs) stay as they are until 3e-4.
- **Cierre:** Resultado · Evidencia · Aprendido, plus the exception lines `Tests: no`, `Build: no`, `no comprobado` and `Secretos: no (<why>)`.
- **Decision:** ✔ when the first choice-window answer came before the task's first change. Each answer is recorded with its position; a later question does not count against it.
- **Gate:** the agent's last gate after its last code change, else the repo typecheck: memory.md *Quality gates* → package.json → tsconfig. The limit is 40 s and the process tree is killed on timeout. A failing gate blocks once. Not applicable when no code changed.
- **Secrets:** strong formats only, in memory.md, mem_save, the lines the task added and its commits. `password=` is masked only in what Waymark writes.

## Alternatives considered
- **Keep parsing the Cierre and fix each case:** each test found new prose variants, and the fixes only patched symptoms.
- **The hook always runs the full gate:** strongest, but each close could take minutes. In a real project one eslint run took 7 minutes.
- **All of 3e at once:** fewer round trips, but a failure would be harder to trace to its part.

## Consequences
- False ✘ from prose parsing disappear, and the agent writes less.
- Context cost per session becomes bounded and measurable.
- Records become portable with the repo (notes), so another clone or agent can read them. Notes need `git push origin refs/notes/waymark` to travel, an explicit step.
- Old records migrate to notes, or are archived with the chain verified.
- The order after 3e: the live Codex test, then step 4 (A/B against gentle-ai), then 3d (adapters).
