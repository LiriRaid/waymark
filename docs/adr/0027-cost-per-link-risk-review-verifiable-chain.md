# 0027 · Cost per link, review by risk, procedures by the hook, a chain anyone can verify

**Status:** accepted (2.0.16, built point by point; each point appends its section here)

## Context

Waymark is a supply chain of the agent's work (`0002`): inputs, stages, outputs, each with evidence the hooks compute, in a record chained by hash and anchored in git. Two things were missing: the cost of the routine was argued, not measured per step, and a chain could be checked only by a test, not by someone who was not there. The goals that govern the release: fewer tokens (measured), better ways of working, agnostic in the full sense (agent, stack, project, branch, area, field, technology, architecture), adaptive, learning over time, and a supply chain that covers 100% of the agent's work.

## Decisions

### 1. Cost per link (point 1)
The evaluation of each task keeps `links` (schema `v: 1`): the task's main-agent responses split into `routine` (a department, waymark, review or docs skill; a `waymark.mjs` subcommand; a read of a procedures file, the project's memory or the waymark references; the choice window), `reply` (a response with no tool call) and `work` (the rest), each with its response count and input, cache-write, cache-read and output tokens. A response with calls of several kinds counts as routine. Source: `turnLinks` in `transcript.mjs`. Measurements: `docs/audit-context.md` §3. Limit: a Read of a waymark reference counts as routine even in this repository, where those files are also the work.

### 2. Review proportional to risk (point 2)
See the amendment of `0010`. The review testigo applies at L2+ only for L3, a sensitive or critical path, more than 4 code files, more than 100 lines, or a size that cannot be counted (a shell command changed files). Everything else records `omitted.Review`. Limits and path lists are `risk` in `routine.json`; a project overrides them in `.waymark/risk.json`. Limit: that file lives in a folder the agent can edit, so an agent could loosen its own threshold; the record shows the override and point 8 guards it.

### 3. Procedures by the hook (point 3)
At the task's first change the pre-tool hook adds the owner department's whole `procedures.md` to the context, once per task and department, next to the file's `pack`. The delivery is stored with the packed state (`procs`) and the `procedure` testigo counts it as read and before the change. The whole file is handed, not a section: choosing a section from the request's words is a guess, and a wrong guess would pass the testigo falsely. Where the agent has no hook before the tool, or no transcript to name the owner, nothing is handed and the agent reads the file as before; the testigo then needs the read. Tests: `tests/false-fails.test.mjs` (delivery once, a delivery of another department does not count, nothing delivered and nothing read still blocks). The department is also handed when it loads (2.0.19): a `Skill dept-*` call (the Claude matcher includes `Skill`) or a read of `dept-*/SKILL.md` by a read tool or a shell command. Before, a department loaded after the first change, because the Stop asked for it, got its procedures only at a next edit that never came, and the testigo blocked again and again. A load after the task's first change is kept as `late`: it counts as read but not before the change, so the testigo records ✘ "after the task's first change" and does not block.

### 4. Skill descriptions (point 4)
The 17 descriptions went from 4,888 to 3,492 characters (`size.mjs`): the redundant "Waymark ·" prefix and the rules that the department's own file repeats were dropped; the Spanish trigger phrases the user says stay. The full session figure went from 13,029 to 11,494 characters. `skill-fit.mjs` needs 14 days of history and had 9, so routing is guarded by the routing tests only; re-run it when it has enough history.

### 5. What the hooks inject (point 5)
Measured by `size.mjs`: the per-prompt reminder from 475 to 251 characters (the rule line 279 to 99; the task line says `Cierre ID: new … ; follow-up (same files) …`; the git line shows a count and the first two file names; the stack line is unchanged), and the held message from 1,306 to 637. The user's own words are not lost to the cap: a held message longer than 520 characters is carried up to there plus a pointer, and the whole text stays in `.waymark/held-full.md`. The card (1,653) and the check pointer (250) are unchanged: point 1 shows no evidence yet that they are read and unused. The instructions block is 6,494 characters (cap 6,500) after point 2 changed one claim.

### 6. `waymark.mjs verify` and the signed release (point 6)
`verify [--install] [--require-signature] [--manifest <file>] [<task ID>]` (`scripts/verify.mjs`) checks, with no network: the chain of the project's records (hash links, the notes in `refs/notes/waymark`, the anchors in `refs/notes/waymark-anchor`) and names the first broken task with one of three reasons (edited line, deleted line, rewritten and chained again); with `--install` the installed files against `skills/waymark/MANIFEST.json` (sha256 of every file under `skills/`, CRLF read as LF, the manifest never lists itself; rebuilt by `scripts/manifest.mjs --write` and checked by `tests/verify.test.mjs`, so it cannot go stale); and the signature of the release tag `v<VERSION>` (else HEAD) with git's own verification against `skills/waymark/ALLOWED_SIGNERS` (git's allowed-signers format, or `gpg <fingerprint>` lines): `signed by <key>`, `signed, key not in ALLOWED_SIGNERS`, `bad signature` or `unsigned`. The exit code is 0 when the chain (and the files) are intact; an unsigned release is a warning unless `--require-signature`, because a user with no signing key must still be able to verify the chain. Each task's record keeps `signatures`: git's verdict per commit. **Amendment (2.0.17, point 2): an install that verifies itself.** Two changes make `verify --install --require-signature` pass on a clean install and on one that has run `sync`. (a) The manifest no longer lists the files `sync` rewrites for each machine, `waymark/skill-map.json` and `waymark/skill-registry.md`; `--install` checks each against its generator instead of a hash (`checkGenerated` in `manifest.mjs`: the map parses and holds the `skills` map, the registry carries the header `sync.mjs` writes). The manifest also leaves out its own signature. (b) The release carries the signature of its manifest: `skills/waymark/MANIFEST.json.sig`, made with `ssh-keygen -Y sign` (namespace `waymark`) over the manifest read with CRLF as LF, by `manifest.mjs --sign <ssh private key>`, and checked with `ssh-keygen -Y verify` against `ALLOWED_SIGNERS`. It needs no git history, so an installed copy checks it: `signed by <principal>`, `signed, key not in ALLOWED_SIGNERS` (a valid signature by a key nobody trusts), `BAD signature` (the manifest or the signature was edited after signing) or `unsigned`. `--require-signature` under `--install` requires this one; in a clone the signed tag is reported next to it, not required. An edited file is caught by the manifest, an edited manifest by its signature, an unknown key by `ALLOWED_SIGNERS` (`tests/verify.test.mjs`, with a throwaway key). A third local change was found while closing 2.0.17: the learning step writes the lessons of the user's own tasks into `## Learned rules` / `## Learned notes` of the department and tool `SKILL.md` files of the install, so any lesson made `verify --install` report that file as changed. `hashFile` (`manifest.mjs`, also what `pinned` records) now hashes a Markdown file without the body of those two sections; the heading stays, every other line is still verified, and removing the section is still a change. The release checklist is: regenerate the manifest, sign it, commit both, sign the tag.

Limits, in these words: without a signature the chain resists accidents and partial edits, not someone who can rewrite the repository and chain it again; the signature of an installed copy proves the manifest is the maintainer's, and the files are proved by the manifest, so whoever controls both the install and `ALLOWED_SIGNERS` can forge it (the keys must come from a source the verifier trusts, such as the tag in a clone); `ALLOWED_SIGNERS` ships with the maintainer's public key.

### 7. `waymark.mjs attest <task ID>` (point 7)
One task exported as an in-toto Statement v1 (`attest.mjs`): `subject` is the commit(s) it produced; the predicate (`https://github.com/LiriRaid/waymark/attestation/task/v1`) holds the request, the decisions (question, option chosen, options discarded, position before or after the first change, date), the evidence (what the Cierre stated, the facts no call backs, the calls), the gates as the hook computed them, the evaluation with `links`, the inputs and, from point 9, the pinned rules, the signature state of the commits, and the chain (the record's hash, its link, the anchor in `refs/notes/waymark-anchor`, the note's commit). `predicateDigest` is the sha256 of the predicate with sorted keys. `verify --attestation <file>` checks the shape, that digest (an edited predicate fails), that each commit exists in the repository, that the log holds a record with the same hash and that the anchor exists. The attestation file itself is **not signed** in this release; signing it, so that it can be trusted away from the repository, is a later option and is not promised.

### 8. Sensitive-path guard (point 8)
The pre-tool hook denies reading and editing the paths of `routine.json` `risk.sensitive` (`.env*`, `~/.ssh`, `~/.aws`, `~/.config/gcloud`, `*.pem`, `*.p12`, `*.pfx`, `*.key`, `id_rsa*`, and the keys of the other ssh types), the same list that makes the review testigo apply (point 2). Exceptions: `risk.allow` (the `.env.example`, `.env.sample` and `.env.template` family), the project's `.waymark/risk.json` `allow`, and the user's `Sensitive allow:` line in `~/.waymark/preferences.md`. A denial is written to `~/.waymark/.denied.json` and the task's record keeps it as `denied`. It acts where the agent's hook runs before the tool: Claude Code's `Read` (added to its hook matcher: an installed copy needs its hooks registered again), the edit tools of every agent, and any shell command whose arguments or redirect target name such a path that exists. **Limits, in these words:** it does not stop what a command reaches without naming the file (`grep -r KEY .`, `find … -exec cat`, a script that opens the file itself); `tests/guard.test.mjs` asserts those bypasses instead of assuming them. An agent whose hook does not see its read tool (Codex, Cursor, others: the capability matrix of point 12) reads through its shell, where only the named-argument case is caught. The project's `.waymark/risk.json` sits in a folder the agent can edit: an agent could add itself to `allow`; the record does not show that edit as a denial, but the change is in the task's files.

### 9. Pinned inputs (point 9)
The record's `inputs` keep what the task was built with (versions, model, MCP servers, hashes of the instruction files); `pinned` (`pinnedRules` in `provenance/snapshot.mjs`) adds which rules governed it: the owner department's `SKILL.md` and `procedures.md`, `routine.json`, the stack and architecture profiles the task read, the project's `.waymark/risk.json` when it exists, and the release `MANIFEST.json`. The hashes are the manifest's (text with CRLF read as LF), so `verify <task ID>` says how many of the pinned files match this release's manifest and names those that differ (another release, or a file edited since). A department name that is not a plain word is never used as a path. The procedures hash is of the whole file, as the hook hands it whole (section 3). Records from before 2.0.16 pin nothing and say so. `attest` carries `pinned`.

### 12. Per-agent capability matrix (point 12)
`scripts/matrix.mjs` generates two tables from `agents/agents.json` and the adapters: the hook events Waymark registers for each agent, and, from them, which steps are *enforced* (a hook runs and can stop the turn, deny a tool or hand the agent text) and which are *advisory* (the agent is told in its instructions; nothing blocks it): end-of-turn checks, the decision gate and commit trailer, memory and procedures handed over, the sensitive-path guard for edits and shell and for reads, and the context brake. An agent with no adapter has no events and is named as such. The tables sit between markers in `README.md` and `INSTALL.md` (`matrix.mjs --write`); `tests/matrix.test.mjs` fails when they differ from the generated text, for an agent with all five events, one without PreToolUse and one with no adapter. "Enforced" is a statement about registered hooks and the adapter's capabilities, not a measurement of each agent's runtime: a hook the agent skips (Codex skips an untrusted one until the user approves it) is not enforcing anything.

### 13. Validation outside the author's projects (point 13)
Waymark was built working on the author's own projects. `tests/external/corpus.json` pins five public repositories unlike them, each to a commit, with what a correct Waymark reports: a Rust CLI (`sharkdp/fd`), a Laravel application (`laravel/laravel`), a Terraform module (`terraform-aws-modules/terraform-aws-vpc`), a Python data-science library (`scikit-learn-contrib/imbalanced-learn`) and a documentation-only repository (`ossu/computer-science`). `scripts/external-corpus.mjs <clones-dir>` measures read-only clones, with no opinion: stack detected, profile applied or `generic`, whether the gate commands of that ecosystem are recognised by the hooks, the characters of the card and the reminder there, the hooks' errors, and the verdict the stop hook gives to two scripted tasks (a README edit; a code edit with a passing test run). The output is structured and versioned (`waymark.external-corpus/v1`) so it can later be read as data.

**What the first run found** (`tests/external/results-before.json`): Rust, PHP and Terraform projects had no stack and fell to `generic` (no profile for them); a Laravel repository was classed Node because its `package.json` holds Vite assets; `terraform fmt -check`, `terraform validate`, Pint and Pest were not recognised as gates or tests. Closed in this release: `stackOf` and the new `profileOf` (`stack.mjs`) detect them, with a rule that a `package.json` naming no JS framework yields to `composer.json` or `Cargo.toml`; three profiles were generated from `templates/stack.template.md` (`stacks/rust.md`, `php.md`, `terraform.md`); the classifier (`runs.mjs`) knows `terraform`/`tofu`/`composer` verbs, Pint, tflint, PHP-CS-Fixer, phpcs and Pest. After: every repository detected, profiled and with its gate commands recognised, no hook error, and no block on the scripted tasks (`tests/external/results-after.json`). The regression cases are in `tests/external.test.mjs` (detection, profile, the classifier table).

**What it does not show, in these words:** the memory bootstrap and the routing to a department are the agent's work, not code, so they were not measured here; the cost in tokens of a small change in each repository needs a real agent run per repository and is not measured, so no figure is claimed; the three generated profiles were written from the tools' documentation and have not run in a live task, and their commands are marked to be verified once; the scripted tasks are synthetic, so "no block" means the hooks do not misjudge a well-formed task in these ecosystems, not that an agent works well there; a repository with a JS framework and a PHP backend is classed Node. The remaining ecosystems of the plan's list (a Kotlin or Swift mobile app, a multi-language monorepo, an embedded C library) move to 2.0.17 by the scope guard, decided by the user.

**Amendment (2.0.17, point 4): Waymark used on real work in eight repositories.** The corpus grew to eight: the five above plus a mobile app (Kotlin, Gradle), a multi-language monorepo (Go, Python, C#, Java, Node services) and an embedded C library, each pinned to a commit with its expected stack, profile and gates (`tests/external/corpus.json`, schema v2, which also holds the task of each). In each clone, in the scratchpad and deleted afterwards, Claude Code ran headless (`tests/external/run-agent.mjs`, Sonnet) with the hooks of the repository checkout, a private `WAYMARK_HOME` and no engram, so none of the author's memory was read or written, and made one small real change (a doc comment, an inline note, a variable description, a docstring, a README line). The choice window was answered by the harness with the recommended option and every answer logged; a shell command outside a short allow list was denied and counted. `tests/external/summarize-runs.mjs` reads what each run left (the record the hooks wrote, the memory the agent bootstrapped, the diff) into `tests/external/results-2026-10-16.json` (`waymark.external-results/v1`, two passes: before and after the fixes below).

**What the first pass found** (16 runs in total; the per-run figures are in the file): `Verificar` (the gate) was ✘ in 6 of 8 runs. Two causes: the change was only a comment, so no gate could tell anything, and the tool was not installed on the machine (`cargo`, `php`, `terraform`, `gradle`, `cmake`, `go`): the hook counted a missing tool as a failure of the code (`go vet`, re-run by the hook) or as "nothing ran". A gate refused by the permission system or stopped by a hook counted as a gate run that passed. The spec rule asked for a test next to a Go file for a comment-only change. Detection left the Android app on `java` rules and the C library on `generic`, and `cmake --build`, `ctest`, `make` and the `assemble*`, `test*`, `lint*` and `compile*` tasks of Gradle were not recognised as gates, builds or tests. The measuring script itself held a fixed task ID that now blocked every scripted task. The memory bootstrap is left to the agent: it asked the user whether to create `.waymark/memory.md` in one run, and 6 of 8 runs wrote one in the first pass, 3 of 8 in the second.

**What changed, each with its case:** `lib/comments.mjs` (`commentOnlyEdit`) judges an Edit by what it replaced: when every changed line is a comment and none is a directive to a tool (`@ts-ignore`, `eslint-disable`, `type: ignore`, a shebang), the edit owes no gate, spec or build; anything it cannot tell is code. A gate whose program is not on the PATH (`runGate` checks before running it) or whose attempt printed "command not found", "permission denied" or a hook error is reported as `the gate could not run here (…)`, with the way out `no comprobado (<why>)`; after the block, `Resultado: parcial (<why>)` is the same exception, recorded as one. Stacks `c` and `android` were generated from `templates/stack.template.md`, with detection (`CMakeLists.txt` or `Makefile` beside C sources; a Gradle build with an `AndroidManifest.xml`). The classifier knows the verbs above. Regression cases: six real transcripts, trimmed, in `tests/corpus/external-*.json` (four fail on the commit before the change), `tests/external-findings.test.mjs` (comment edits in several languages and what is not one, a missing tool, a refused run, the partial result), and the detection and classifier tables.

**Result of the second pass** (clean clones; `tests/external/results-2026-10-16.json`): `Verificar` ✘ in 2 of 8 runs (a Terraform change, which is code, and a Python docstring, which is not recognised as a comment, with no toolchain to run); one run skipped the routine on a README line (✘ on the decision and on the routing, recorded as they happened); the other five runs ended with no failed step. Cost as reported by Claude Code: 8 runs, 97 turns, 1.595 USD in the first pass and 8 runs, 93 turns, 1.25 USD in the second; the cache-write tokens of the routine link were 169,098 against 93,702. These are single runs of one model, so the difference between passes is not a measured saving.

**What it still does not show, in these words:** none of the toolchains of these repositories is installed here, so whether a gate passes on them is not measured, only how Waymark treats one that cannot run; one run per repository and pass, so the variation between runs is not measured (the README run skipped the routine in one pass and not the other); the harness answers the choice window with the recommended option, so the decision step is measured against that answer only; the last change (the partial result as an exception) was verified with a corpus case and specs, not with a third pass; no comparison with a session without Waymark or with any other tool was run, so no saving is claimed; routing is recorded, not judged; a Python docstring and a Terraform description are code for these rules; the memory bootstrap stays the agent's work and varies between runs (a hook that writes it from the detected stack and profile is proposed for a later release).

## What 3.0.0 will need from the records (not built in 2.0.16)
The author plans machine learning over the records for 3.0.0. Nothing of it is implemented here and the door stays open: what the records keep must be structured, versioned and labelled, so a later reader does not have to guess. State of each family of fields after this release, and why it matters:

| Family | Fields today | Why a model needs it | Missing |
|---|---|---|---|
| Version of the shape | `schema` (`waymark.record/v1`), `links.v`, the attestation's `predicateType`, the external corpus's `schema` | to read old and new records together and to know which fields can be absent | a migration rule when v2 appears |
| Inputs | `inputs` (versions, model, MCP, instruction hashes), `pinned` (department, procedures, routine, profiles, risk override, manifest) | the same request under other rules is another example; without the rules a label is noise | the request's task type as a label (it is free text in `prompt`) |
| Decisions | `decisions` (question, chosen, discarded, position) | the user's choice is the strongest label of what is right here | the options' own attributes (risk, cost) as fields, not prose |
| Outcome | `outcome.result` (hecho, parcial, bloqueado), `evaluation.steps` (✔, ✘, ⚠ per testigo), `evaluation.omitted`, `unresolved`, `findings` | the target a model predicts | the later verdict of the user (accepted, reverted), which no hook sees |
| Cost per step | `evaluation.usage`, `links` (routine, work, reply), `evaluation.quotaPct`, per-gate seconds | to learn which steps are worth their tokens | cost per tool call (the transcript has it; the record keeps only the split) |
| Context | `level`, `department`, `files`, the stack profile read, `signatures`, `denied` | features of the task | the project's kind as a label (the external corpus has `field` and `language` for its five repositories only) |

Two rules follow. A field is added, not repurposed: records are chained and old lines are never rewritten. A label that a person would have to type by hand is not asked for; it is derived by a hook or left out.

### 10. README: what it is and what it is not; English documentation (point 10)
The README gained a section that says what Waymark is (a chain of custody for the agent's work) and is not (an environment installer, an orchestrator, a workflow framework, a dependency audit), a table of what it records with the test or file that backs each statement, and a list of what it does not do (records and attestations unsigned; stops only where a hook runs; no published token comparison; measured on five outside repositories only). It names no other project and compares nothing. The size table is generated (`size.mjs --readme`, between markers) and the ADR index too (`docs-gen.mjs`). The documentation prose was already English except the sample messages of INSTALL §1, §8 and §11, the option labels and the evaluation template, now translated with a note that the agent shows them in the user's language. Kept in Spanish on purpose: the phrases a user says (trigger lists, quoted examples) and the text the hooks print for the user.

### 11. Documentation drift test (point 11)
`tests/docs.test.mjs` fails when: `VERSION`, `.claude-plugin/plugin.json` and the first CHANGELOG entry differ; a figure of the README size table differs from `size.mjs --readme` by more than 5%; a documentation file holds Spanish prose outside the allowed places (`spanish()` in the test is the detector, with a test of its own); a record is missing from the README's ADR index; README or INSTALL name a `waymark.mjs` command that does not exist. It runs with `node --test tests/*.test.mjs`, so the existing gate catches it. Limit: the language detector reads stop-words and accents, so a short Spanish line with neither can pass.

## Appendix: the claims the README may make, and where they come from (point 0)
Own side: the fixed context per session and the per-prompt reminder are `size.mjs` figures; gates, review and build computed by hooks (`routine.json`, `tests/integrity.test.mjs`); evidence checked against tool calls (`tests/supply-chain.test.mjs`); the chain, its anchors, `forget` and the rebuild from git (`tests/supply-chain.test.mjs`, `tests/memory-chain.test.mjs`, `tests/verify.test.mjs`); stack and architecture profiles (`skills/waymark/stacks`, `skills/waymark/architectures`); the per-agent matrix (`matrix.mjs`).

Another project in the same space was read on 2026-10-15 (read-only, not run; its name, address and commit are not recorded here). What was read and what it showed, with no judgment of the project, citing only file and line: `internal/reviewtransaction/bundle.go` (lines 1-60 and 141-153) defines an exportable, hash-chained review bundle with a bundle digest re-checked on import; `internal/cli/review_stop_hook.go` is a Stop and SessionStart hook that prints one reminder and never runs the review; `internal/releaseprovenance/provenance.go` (lines 1-60) builds a release provenance manifest; `internal/releasepolicy/policy.go` validates the release configuration and carries its minisign steps; `internal/verify` is an install health-check runner; `internal/recoverytrace` ledgers per-path dispositions of a repository recovery; `internal/components/mutationjournal/journal.go` keeps before-images for install rollback. Not read: the rest of each package, how its review chain records decisions or gates, and anything at runtime. The rule that follows is the one the user set: Waymark states only what it can cite about itself, never that another project lacks something, and every comparison ends in something Waymark measures or tests.
