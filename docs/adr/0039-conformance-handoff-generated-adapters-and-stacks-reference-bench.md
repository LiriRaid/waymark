# 0039 · Conformance across adapters, handoff between agents, adapters and stacks that draft themselves, and the reference bench

**Status:** accepted (2.0.18, point 11). Amends ADR 0022 (an adapter is now judged by a list, and a new one is drafted by a command) and ADR 0027 (the external corpus measured detection on eight repositories; the reference bench measures a list the user keeps outside the repository).

## Context

Waymark claims to be the same chain in every agent: a card at the start, a gate before the first change, a Cierre at the end, a record in git. Each of the eight adapters had its own tests, written when it was written, so nothing said they behave the same, and the claim was only as good as the last agent someone tried. The plan asks for criterion 9 (agnostic and adaptive) and 12 (self-generating) to be shown without running agents in other people's projects: one list of behaviours that every adapter passes, a task that moves from one agent to another, a command that drafts what is missing, and a bench over repositories unlike the author's own.

## Decision

The choices are the user's (2026-10-17): the cases run the real hooks with one driver module per agent; the five agents Waymark knows without an adapter stay without one; the reference list is the eight repositories the user picked.

- **One list, every adapter** (`tests/conformance/`). `cases.json` lists 35 behaviours (the card at the start, the per-prompt reminder, the decision gate, the commit trailer, the sensitive-path guard and its detection, the memory handed with the first edit, the choice window recorded, the end of the turn and the record, resuming), each implemented in `cases.mjs`; a test fails when the two lists differ. Each agent has a driver (`agents/<key>.mjs`) that says what happens the way that agent documents it: its hook payloads and answers, and its transcript (a rollout, a chat, an events log, the SDK's messages) or, where it has none, the events Waymark journals. A *world* (`harness.mjs`) is a real project folder with Waymark's memory, a session and its own `WAYMARK_HOME`; a case drives it with neutral steps (a prompt, a reply, a skill, a tool call, a choice-window answer, a stop), the harness runs the real hook scripts with `--agent <key>` and the case reads what they answered and what they recorded. A case never knows which agent it runs on, only what the driver says it can do (`caps`: whether a hook carries the reply, whether the prompt hook can add context, whether anything runs before a read, whether the answer to the choice window is carried). A case whose need an agent lacks is not run there; `adapter.capabilities-are-what-the-adapter-says` checks each declared capability against the adapter's own exports, so a lack is never claimed without being true. 243 case runs over the eight agents; the agents run side by side.
- **What the list found** (each fixed here, each now a case): the owner department was read from the transcript raw, so for every agent whose transcript is not Claude Code's `.jsonl` the hook never found it and never handed over the procedures (the agent had to read them, and was blocked until it did); OpenCode's plugin did not pass the transcript to the hook after a tool, for the same result; Kiro's tool result, when an object, was not read for its output, so a secret a command printed was invisible to the detection of ADR 0037; and every adapter but Claude Code dropped the description of each option of the choice window, so the check of ADR 0038 would have called every window of those agents attribute-less.
- **Handoff** (`tests/handoff.test.mjs`). A task closes under one agent's payloads and a second task is left open (a quota, a crash); another agent starts a session in the same project. The ring goes through all eight (each agent writes once and continues once): the next agent finds the project memory, the last closed task and the open one in `tasks.md` (with the agent that started it), is offered the next number and the follow-up, is handed the precedent of the earlier task (where both agents carry the prompt), and closes its own task in the same chain, which `verify` reports intact with both agents' records. Antigravity's hooks carry no prompt, so there is no precedent to find or to hand over, and the test says so.
- **`waymark.mjs adapter-new <agent>`.** Drafts the adapter of an agent `check` lists without one, from `templates/agent-adapter.template.mjs` and what the agent's documentation says (flags: `--name`, `--dir`, `--instructions`, `--shell`, `--edit`, `--read`; the rest comes from `agents.json`). The draft speaks Claude Code's shapes with the agent's tool names read back as the core's, marks every guess `TODO(docs)`, and goes to the private layer (`~/.waymark/drafts/adapters/<key>/`), untracked, with its conformance driver, its entry for `agents.json` and its doc. It runs the suite on the draft in a copy of the skills where it is registered (`WAYMARK_CONFORMANCE_SCRIPTS`, `_DRIVERS`, `_ONLY`), says how many checks pass and which cases fail, and a draft already in the folder is judged as it is, so the user adapts it and runs the command again. `--install`, the user's yes, runs the suite again and refuses a draft that does not pass; it then registers the adapter in `agents/index.mjs` and `agents.json`, writes its doc and its driver (which joins the roster by being in `tests/conformance/agents/`). From an install with no repository around it the suite is not there: the draft is written, the command says so, and nothing installs. This release drafts no adapter for the five agents Waymark knows without one (Windsurf, Qwen Code, Droid, Amp, Crush): none runs on the author's machine, nothing can be tried live, and an adapter written from documentation alone would install hooks nobody has seen work. Scorecard check 9.1 (every known agent has an adapter) stays failing and the README says so.
- **`waymark.mjs stack-new <path>`.** Drafts a stack profile for a repository with none, from its manifests, its scripts (`package.json`, `composer.json`, a Makefile) and its CI files, into the template's sections: the signals it found, a Commands table where every gate says "to verify once", and the project-memory table. It runs nothing and writes only to the drafts folder (or `--out`); a yes moves it into `stacks/`. Fourteen ecosystems (Rust, PHP, Terraform, Go, Python, .NET, Android, Java, Ruby, Dart, Elixir, Swift, C, Node), the first match decides; the CI commands that look like a gate are said beside the proposal, never replacing it. The rust, php, terraform and android profiles are deleted from a copy of the skills and drafted again from their fixtures: the draft names no signal the shipped profile does not, names the shipped profile's first one, proposes the four gates and every command it proposes is a command the shipped profile gives.
- **The reference bench** (`bench/reference.mjs`). The list of repositories lives in `~/.waymark/reference-repos.json`, outside the repository, so no tracked file names another project; the bench clones each one shallow and read-only into a temp folder, measures with no opinion and no agent, and deletes the clones. For each: the stack and profile Waymark detects, what `stack-new` would say and the layout; the gates it proposes and whether the hooks recognise each as a gate, a test or a build; the agent assets the repository carries and the orchestrator blocks in them; the size of what Waymark injects there against the size of those assets; and the failures, by kind (`no-stack`, `no-profile`, `no-draft`, `gate-unknown`, `hook-error`). Nothing in a clone is ever run: only Waymark's own scripts read it.
- **What the bench found** on the eight repositories, each fixed and now a fixture and a case (`tests/reference/fixtures/`, `tests/reference-regressions.test.mjs`): a build tool run with a flag first (`mvn -q test`, `cargo +nightly test`, `make -j8 test`) was taken for no test, no build, no gate (the verb is the first word that is no flag); Dart and Flutter, Elixir and Swift commands, `dotnet format --verify-no-changes` and `gofmt -l` were not gates, tests or builds to the hooks; the card said nothing of a Maven, Gradle, Android, .NET or Dart project (the stack module names them now, one short line); a profile drafted for an ecosystem could not be used without a code change (a profile in `stacks/` under the ecosystem's name applies now); and a clone failed on Windows for a long file name (`core.longpaths`). One failure remains by design: an ecosystem with no profile of its own (Dart) falls under the generic one, which `stack-new` exists to answer. Measured, not failed: two of the repositories are themselves agent tools and carry 152,614 and 164,721 characters of their own agent assets (43 files in one); Waymark injects about 10,400 to 11,000 characters there, between 0.06 and 0.07 of what those two carry, and about 3.6 times the 2,892 characters of the one other repository that carries any. None of the eight carried an orchestrator's blocks, so guest mode was detected where it would apply and never exercised there; its own tests (ADR 0022 onwards) cover it.

## What it proves, and what it does not

That the eight adapters behave the same on the same list, as far as the list goes, and that a draft is judged by the same list; that a task can change agents without the next one losing the memory, the record or the chain; that detection and gate recognition hold on repositories the author did not write. It does not prove any adapter works on a live session: the payloads are the ones each agent's documentation (or its journal) says, as the drivers write them, and a driver can be wrong where the documentation is. It runs no agent, so how an agent uses what the hooks hand it is not measured. The bench reads layout and manifests; it does not detect an architecture, and a repository whose gates are only in a script it does not read shows none. Eight repositories are a sample.

## Alternatives considered

- **Cases over the adapter's exports only.** Much shorter, but it would not have found any of the four defects above, all of which live between the adapter and the hook. Rejected.
- **Drafting the five missing adapters now.** Scorecard 9.1 would pass; no adapter would have run. Rejected for saying so.
- **Redefining 9.1** as "known and listed, and `adapter-new` can write it". It passes today and changes what 95 % meant halfway. Rejected unless the user decides it.
- **A stack profile shipped for Dart.** A profile written without a project to run it on. `stack-new` drafts it where it is needed, and the profile applies by being put in `stacks/`.

## Consequences

- Scorecard checks 5.6, 9.5 to 9.8 and 12.3 to 12.5 pass; 9.1 does not.
- The suite adds about three minutes to a full run (the conformance cases) and a minute and a half more for `adapter-new`'s own test, which runs it twice.
- A new adapter's driver in `tests/conformance/agents/` is all it takes to be judged; the roster is the folder.
