# Protocol · L2 (Entry and Exit)

Part of the `waymark` core skill; paths are relative to `<skills-dir>/waymark/`. Read it at L2+, after the instructions block: it adds only what the block does not say. L3 adds `protocol/l3.md`; a second failed attempt, `protocol/stuck.md`; a task moving to another department, `protocol/handoff.md`; a session growing large or a sub-agent to launch, `protocol/tokens.md`.

## Entry

1. **Project memory.** The project root is the nearest folder with a manifest (`package.json`, `Gemfile`, `pyproject.toml`, `go.mod`, `pom.xml`, `*.csproj`, `Cargo.toml`, `composer.json`, `pubspec.yaml`). The memory exists but has no *Project map* → run the minimal project scan of `references/project-detection.md` once and add it. A private-layer file missing (`profile.md`, `preferences.md`, `subagents.md`, `projects.md`, `agent.md`) → create it from `templates/private-layer/` without asking; with no project memory, read `~/.waymark/profile.md` first (the user's defaults).
2. **Stack profile.** Read `stacks/<stack>.md` in full. Unknown stack → `stacks/generic.md`.
3. **Architecture profile.** Read `architectures/<architecture>.md`. Unknown → derive it from the project and generate the profile (`references/project-detection.md`); ask only if the code is ambiguous. Record it in project memory.
4. **Learnings.** Read `~/.waymark/learnings/<department>.md` if it exists.
5. **Tools.** The department's *Tools* table: the skills and MCP servers whose *When* matches the task and whose *Level* ≤ the current level. No installed provider → `skill-registry.md`, then `references/skills.md`.
6. **Brief.** Number the requirements of the `Pedido` line (`1) … 2) …`). Below the block's `Pedido` and `Reutiliza` lines add `Qué: <what> · Para qué: <why> · Dónde: <path>`. *Captura* names what the image points at (screen, element, state, the mark the user drew), not the whole picture; image and text disagree → ask once.

The decisions the choice window foresees include data design, visual style, behavior and defaults; the record keeps each answer with its position (before or after the first change).

## Exit (Definition of Done)

1. **Quality gates** — the commands from project memory (or the stack profile): typecheck · lint (changed files) · related tests · build. Never rerun a full gate with no change in between (a real L2 spent 13 of 26 minutes in two whole-project typechecks). Report real output; never claim done with red gates.
   - A failure that is not this task's: prove it in a clean copy of HEAD (`git worktree add <tmp> HEAD` → rerun → `git worktree remove <tmp>`); never stash the user's changes.
   - Not allowed to run a gate → `no comprobado (sin permiso para <command>)` instead of retrying.
   - The user skips a check for this task ("no hagas tests", "sin code-review") → `omitido (usuario: "<their words>")` in the Cierre; the next task, or "ahora sí", returns to the defaults.
   - No spec for the changed code: add one where the project already tests that kind of file; otherwise write "sin infraestructura de test" and give the user a one-line check.
2. **Architecture conformance** — the profile's *Conformance checklist* against the changed files: ✔/✘ with `file:line`.
3. **Review** — `code-review` on the task's files when the change is risky (L3, a sensitive path, or over the `risk` limits of `routine.json`); a small plain change records `omitido: riesgo bajo`.
4. **Department DoD** — tick the department's *Definition of Done*.
5. **Learn** — `references/learning.md`. The lesson goes in the Cierre's Aprendido; the end-of-turn hook writes *Work in progress* and saves it to engram.
6. **Cierre** — as in the block, plus `Pedido: ✔1 <evidence> · ✘2 <why not>` for a numbered Pedido. It holds only what the agent alone knows; the end-of-turn hook computes the rest from the tool calls (memory, procedure, gates and their order, tests, review, docs, branches, time, tokens) and appends the task's record to `<project>/.waymark/provenance.jsonl` (docs/adr/0002, 0004, 0012).
