# Protocol · L3 (plan as checkpoints)

Read after `protocol/l2.md` when the task is L3 (refactor, migration, new project). `dept-architecture` owns it.

**A structural change is its own question** (files between layers, split or merged files, a new kind of folder): its own choice window, even when the user picked "recommended" for the rest. `dept-architecture` → *Structural change* says what the window shows (`W convention --move <from> <to> --files N`).

**One ask is one task.** The steps below are done in this same task, never handed to a later one: the window does not offer "only phase 1" to shrink the ask, a pending step is not a reason to close `parcial`, and the user's next message on it continues it (same ID, `b`).

Long tasks fail when the conversation is compacted and the agent loses what was done, what is next and what was ruled out; it then fills the gaps by guessing. Keep that state on disk, not in the conversation:
1. Plan first (`Plan` agent or plan mode) and split it into steps that are each an L1/L2 change with its own gate. Write the decision in an ADR.
2. Write the steps into the Cierre's Aprendido (≤200 characters; the end-of-turn hook makes it the task's *Work in progress* line): `✔1 <step> · ▶2 <step> · 3 <step> — next gate: <command>`.
3. Mark a step ✔ only after its gate passed; what was ruled out goes in the ADR or the commit (the whole Cierre stays in the task's record).
4. After a compaction or a new session, the session hook re-injects the line: resume from `▶`, re-run its gate before continuing (`W tasks <task ID>` shows the whole record). `/compact` is safe mid-task once that line holds the plan.
5. Delegate only broad searches (an exploration agent returns the conclusion, not files); the main agent keeps the plan and the edits.

**Exit at L3:** the full test suite instead of the related tests; after `code-review`, also `simplify` and, if the change touches security, `security-review`.
